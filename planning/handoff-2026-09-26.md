## 1. Struttura del sito

Navigazione principale (`docs/.nav.yml`, verificata da `tools/check-docs.py`):

```
Inizia | Processi | Documenti | Integrazione | Intelligenza artificiale | Amministrazione
(+ Parti comuni, senza scheda in alto)
```

| Scheda | Cartella | Contenuto |
|---|---|---|
| Inizia | `index.md` + `tutorial/` | Home (vetrina) e percorsi: Tutorial, Corso base, Corso avanzato |
| Processi | `modelli-di-processo/` | Designer, elementi, operazioni, eventi; parte operativa (To-Do List, ricerca processi) |
| Documenti | `classi-documentali/` | Classi documentali, ricerca documenti, dossier |
| Integrazione | `integrazione/` | API standard, Coda delle chiamate, Strumenti nel processo |
| Intelligenza artificiale | `intelligenza-artificiale/` | Solo segnaposto |
| Amministrazione | `amministrazione/` | Gruppo "Configurazione" (ex Menu Configurazione) + Sistema |
| Parti comuni | `parti-comuni/` | Variabili, formule e script, dashboard, report, glossario. Scheda nascosta via CSS, raggiunta dai link e dalla home |

Le cartelle decidono gli URL; i file `.nav.yml` (plugin awesome-nav) decidono ordine, etichette e gruppi virtuali (es. "Configurazione" in Amministrazione, "Strumenti nel processo" e "Operazioni" in Integrazione).

### Integrazione (la sezione lavorata in questa sessione)

```
Integrazione (index)          due macro-temi, "integrazione ordinata", strumenti, collegamento variabili, scenari
├─ API standard               index, autenticazione, processi, attività, documenti, utilità + collection Postman
├─ Coda delle chiamate        ChiamateAPI, stored procedure BPM_CreateNewProcess, convenzione EXTERNAL ID
└─ Strumenti nel processo
   ├─ Connessioni esterne · Dati esterni nelle variabili
   ├─ Operazioni → Carica Dati · Esegui SQL
   └─ Connettori → File System · Mail · Web Service (parte generata inclusa da snippets/)
```

## 2. Decisioni prese (dettaglio in `Roadmap.md`, "Decisioni del 23/9")

- Tutorial e riferimento possono ripetere concetti; il riferimento è la fonte completa.
- Ogni informazione si documenta dove si configura; dashboard e report si configurano in Parti comuni ma si consultano da menu personalizzati e schermate di processo.
- Integrazione e Intelligenza artificiale sono schede separate. Nell'Integrazione: API standard (l'esterno pilota BPM) nettamente distinte dagli strumenti nel processo (BPM prende l'iniziativa).
- La Coda delle chiamate è un'**alternativa** alle API standard, non un'altra API.
- Terminologia (in `CONTEXT.md`): **Operazione** (oggetto della palette), **Connettore attivo** (unica porta alle operazioni dei connettori), **Start su evento** (porta agli eventi), **Funzione di un connettore** (operazione / evento / azione client). "Interfaccia" è il termine del manifesto, da evitare.
- Connettori divisi per argomento, non in un catalogo unico: Integrazione (FileSystem, Mail, WebService + Carica dati, Esegui sql); Documenti (Utility, PDF, Spreadsheet); IA (Cs AI + ricerca semantica); SAM a parte; CreditSafe e PowerBI ("servizi aggiuntivi") ancora da collocare.

## 3. Regole editoriali emerse

- Nel sito niente "da verificare", niente riferimenti a bug, niente campi interni o obsoleti: tutto questo va solo nei file `planning/todo-*.md`.
- Esempi di codice brevi, con `…`; esempi completi nella collection Postman (vedi `CONTRIBUTING.md`, "Esempi di codice").
- Dati reali di clienti mai nelle pagine: segnaposto (`<chiave-api>`, `mrossi`…).
- Non insistere sul client desktop (il Designer passerà al web).
- Esegui Programma non si documenta.
- Nomi di funzioni e parametri dei connettori non si cambiano; descrizioni miste italiano/inglese accettate finché non si sistemano i manifesti.

## 5. Strumenti e script

| Script | Uso |
|---|---|
| `tools/check-docs.py` | Controllo inventario e navigazione (CI). Aggiornato alla nuova struttura. |
| `tools/genera-connettori.py <manifesti> snippets/connettori` | Genera le tabelle di riferimento dei connettori dai manifesti JSON (`D:\BPM\Application\Core\Resources\Connectors\WKF.Connectors`). Esclude SAM e le interfacce di tipo tabella. |
| `tools/export-docx.py [sezione]` | Esportazione Word "grezza" (tutto il sito o una sezione). Gestisce gruppi di navigazione, snippet, icone. |
| `tools/genera-manuali.py [designer\|integrazione\|ai\|admin]` | Manuali M-BPM-*.docx con il modello aziendale `export/M-BPM-template.docx`: copertina con titolo, indice (da aggiornare a mano in Word), stili del modello, tabelle con bordi grigi, codice su fondo grigio, riquadri con filo azzurro, link esterni resi testo. |

Dipendenze aggiunte: `mkdocs-glightbox`, `python-docx`, `docxcompose` (`pyproject.toml`, `requirements.txt`, CI). Serve Pandoc.

Altre risorse:

- `docs/integrazione/api-standard/postman/`: collection e ambiente Postman (scaricabili dal sito). Versione Bruno in `api-collection/bruno/`.
- `planning/fonti/`: racconto della demo, sintesi Swagger, Word WebService Standard (+ immagini).
